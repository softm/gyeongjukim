## 검증의 한계와 게시 상태

- 실행 환경에서 Node 자식 프로세스가 제한되어 `npm run check`의 통합 구문 검사 실행이 차단됐다. 구문 검사를 생략한 것이 아니라, 각 파일의 `node --check`를 별도 실행하고 참조 검사만 별도 모드로 수행했다. 일반 GitHub Actions 환경은 기본 `npm run check`를 사용한다.
- 행사 응답 확인 이후 브라우저 도구의 URL 정책 제한으로 추가 탐색·관측이 차단됐다. 새로고침 후 기록 유지, 내 공간, 커뮤니티 작성, 모바일 실화면은 브라우저 전체 흐름 검증을 완료하지 못했다.
- 모바일·태블릿 반응형 CSS, 44px 터치 영역, 키보드 초점, 큰 글씨·동작 감소 설정을 구현했으나 실제 고령 사용자 사용성 검증은 하지 않았다.
- 2026-10-20 사용자 지정 저장소 [softm/gyeongjukim](https://github.com/softm/gyeongjukim)의 존재, 공개 범위와 쓰기 권한을 확인했다. 패키지명·배포 스크립트·로컬 프로젝트 경로·안내 링크를 `gyeongjukim`으로 변경했다.
- 최신 원격 게시 상태는 [Pages 워크플로 실행 결과](https://github.com/softm/gyeongjukim/actions/workflows/pages.yml)를 기준으로 확인한다. `scripts/deploy-ghp.sh`는 인증된 개발 환경에서 소스 업로드와 Pages 설정·실행을 처리한다.
- 저장소명 변경과 무관하게 기존 브라우저 기록과 일정의 연속성을 유지하도록 localStorage 키, ICS UID, 백업 포맷 식별자는 유지했다.
- 실제 회원 인증, 서버 권한, 공유 데이터베이스, 문자·푸시 알림, 공식 족보 원본 연동은 현재 범위에 포함되지 않는다.

## 단일 HTML

`node scripts/export-preview.mjs preview.html`은 CSS·아이콘·이미지·JavaScript를 모두 포함한 다운로드용 단일 HTML을 생성한다. 소스 모듈은 그대로 유지하며 GitHub Pages는 원래의 모듈 버전을 배포한다. 다운로드용 HTML은 외부 네트워크 자원을 요구하지 않는다. 브라우저가 로컬 파일 저장을 차단하면 화면은 열리지만 저장은 실패 안내를 표시할 수 있다.
